Linear System Types

BlockLinearSystems.SparseBlockLinearSystem — Type
SparseBlockLinearSystem{T}(sparsitytransposed::SparseMatrixCSC{Bool, Int}, rowblocksizes, colblocksizes=rowblocksizes)
SparseBlockLinearSystem{T}(nnzvals, indicestransposed, rowblocksizes, colblocksizes=rowblocksizes)

Cache-friendly block-sparse matrix storing each non-zero block contiguously in column-major order within a flat data::Vector{T} buffer.

The block sparsity pattern is provided transposed (sparsitytransposed has size (length(colblocksizes), length(rowblocksizes))) so that blocks along a block-row are contiguous in the CSC structure of indicestransposed.

Fields

  • data::Vector{T}: Contiguous storage for all non-zero block entries.
  • indices::SparseMatrixCSC{Int, Int}: Cached start indices in data for each block (row, col).
  • indicestransposed::SparseMatrixCSC{Int, Int}: Transposed start indices in data (indicestransposed[col, row]).
  • rowblocksizes::Vector{UInt8}: Row dimensions of each block row.
  • columnblocksizes::Vector{UInt8}: Column dimensions of each block column.
  • m::Int: Total number of scalar rows.
  • n::Int: Total number of scalar columns.

Example

using BlockLinearSystems, SparseArrays

sparsity_t = sparse([true false; true true])
bsm = SparseBlockLinearSystem{Float64}(sparsity_t, [2, 3], [2, 3])
block(bsm, 1, 1) .= [1.0 2.0; 2.0 4.0]

DenseBlockLinearSystem{T}(rowblockoffsets, columnblockoffsets=rowblockoffsets)
DenseBlockLinearSystem{T}(data::AbstractMatrix{T}, rowblockoffsets, columnblockoffsets=rowblockoffsets)
DenseBlockLinearSystem(data::AbstractMatrix{T}, rowblockoffsets, columnblockoffsets=rowblockoffsets)

Block-partitioned dense matrix backed by a matrix buffer data (such as Matrix{T}, SubArray, or FixedSizeMatrix{T}) alongside 1-based sentinel-terminated block offset vectors rowblockoffsets and columnblockoffsets.

Fields

  • data::AbstractMatrix{T}: Underlying matrix buffer of size (rowblockoffsets[end]-1, columnblockoffsets[end]-1).
  • rowblockoffsets::Vector{Int}: 1-based start row of each block row, terminated by m + 1.
  • columnblockoffsets::Vector{Int}: 1-based start column of each block column, terminated by n + 1.

Example

using BlockLinearSystems

Conversion & Symmetrification

BlockLinearSystems.symmetrifyfull — Function
symmetrifyfull(M) -> Matrix{T}

Constructs a full symmetric Matrix{T} from a lower-triangular block matrix M (SparseBlockLinearSystem or DenseBlockLinearSystem). Allocates and returns a new symmetric Matrix{T}. See symmetrifyfull! for the in-place version.

Example

using BlockLinearSystems

bdm = DenseBlockLinearSystem{Float64}([1, 3, 5])
bdm[3, 1] = 4.0
mat = symmetrifyfull(bdm) # mat[1, 3] == 4.0, mat !== bdm.data
BlockLinearSystems.symmetrifyfull! — Function
symmetrifyfull!(bdm::DenseBlockLinearSystem) -> AbstractMatrix{T}
symmetrifyfull!(mat::AbstractMatrix{T}, bsm::SparseBlockLinearSystem{T}, blocks=nothing)

Symmetrifies a lower-triangular block matrix in-place:

  • For DenseBlockLinearSystem: mirrors the lower triangle to the upper triangle of bdm.data in-place and returns bdm.data.
  • For SparseBlockLinearSystem: populates preallocated dense matrix mat in-place. If blocks is a vector of block indices, extracts and symmetrifies only the principal submatrix corresponding to blocks.

Example

using BlockLinearSystems, SparseArrays

bsm = SparseBlockLinearSystem{Float64}(sparse([true true; false true]), [2, 2], [2, 2])
block(bsm, 2, 1) .= 3.0
mat = zeros(4, 4)
symmetrifyfull!(mat, bsm)

Schur Complement Reduction

Data structures and kernels for bipartite problems, where a few retained variable blocks are coupled to many small eliminated variable blocks. See the Schur reduction tutorial.

BlockLinearSystems.SchurStructure — Type
SchurStructure

Metadata describing bipartite variable partitioning, block offsets, and coupling sparsity.

BlockLinearSystems.SchurBlockMatrix — Type
SchurBlockMatrix(structure, R, E_data, C_data; pattern=nothing)

Block Hessian structure partitioned into the retained blocks R, eliminated blocks E_data, coupling blocks C_data, and bipartite indexing structure::SchurStructure.

pattern optionally carries the result of build_schur_pattern for this structure, so that code which receives only the matrix can build a reduced system without recomputing it. nothing (the default) means "build it when needed". The pattern must come from build_schur_pattern(structure; extra_blocks=retained_block_pairs(R)), or from a superset of those pairs; only its size is checked (size(pattern.S_sparse, 1) == structure.nr, else ArgumentError).

The pattern is shared between every system built from H, including its copy_structure copies, so treat it as read-only structure: in particular, copy pattern.S_sparse before using it as value storage. Callers may attach extra entries to the named tuple (for example merge(pattern, (S_factor = fac,))); this package ignores entries it does not know.

The positional form SchurBlockMatrix(R, E_data, C_data, structure) (field order) is also accepted.

BlockLinearSystems.SchurReductionWorkspace — Type
SchurReductionWorkspace{T}

Pre-allocated scratch memory and caches for parallel Schur reduction and back-substitution.

The reduction runs in two phases. Phase 1 (parallel over chunks of eliminated blocks) factors every E_e, caching E_inv, z_e and W_er = E_inv * C_er (W_data, laid out like C_data). Phase 2 (parallel over col_chunks, disjoint ranges of retained blocks) has each chunk write straight into the columns of S (and entries of g_S) that it owns, so no per-chunk copies of S are needed and nothing has to be merged afterwards.

trial_workspace(ws::QRReductionWorkspace)

A workspace for a second system with the same structure: its own factored tables and failure flag (the factored tables are needed for back-substitution after the solve), with the scratch shared.

BlockLinearSystems.backsubstitute! — Function
backsubstitute!(x_e, x_r, structure, C_data, E_inv_data, z_data)

Recover step Delta xe for all eliminated blocks independently using cached Einv and z: x_e = z_e - E_e^-1 * (sum_r C_er x_r) for each eliminated block e. The coupling sum is accumulated first and E_inv is applied once per eliminated block.

backsubstitute!(x_e, x_r, ws::QRReductionWorkspace)

Recover the eliminated variables from the retained ones after reduce_qr!: x_e = U⁻¹ (q - B x_r) for each eliminated block, from the top rows of its factored table. Equals the Schur x_e = E⁻¹ (b_e - C x_r) of H = JᵀJ + λ·Diagonal(s). Static up to D_STATIC dimensions, dynamic above (using the workspace scratch), threaded over chunks of eliminated blocks; allocation free on the serial path.

BlockLinearSystems.fast_bAb — Function
fast_bAb(H::SchurBlockMatrix, dx::AbstractVector) -> Real

Compute quadratic form dx' * H * dx in O(N) operations without materializing the full Hessian. dx may have any element type; the result has the promoted type.

The retained part (R) is walked block by block. The eliminated part (E and the couplings C) is where nearly all the work is, and is processed per group of eliminated blocks of uniform dimension with that dimension known statically (3.4x faster than per-block run-time sizes on a bundle-adjustment-like benchmark with 200 retained and 20000 eliminated blocks). Specialising the retained part by run of retained block sizes was measured too: it saved nothing measurable (that part takes ~0.01 ms) and cost 0.2-2 s of extra compilation, so it is not done.

fast_bAb(src::Union{SchurBlockJacobian, QRReductionWorkspace}, v) -> Real

‖J v‖² = vᵀ(JᵀJ)v for v = [v_r; v_e], from the tables, without forming anything: the analogue of fast_bAb(::SchurBlockMatrix, dx) for the Hessian JᵀJ. From the factored tables the damped Jacobian is used, so the result includes λ * Σ s_e v_e² (equal at λ = 0). Any element type of v; the result has the promoted type.

BlockLinearSystems.retained_block — Function
retained_block(H::SchurBlockMatrix, i, j[, rows, cols])

Mutable view of block (i, j) of R, d_i × d_j. For a dense R (a Matrix) any block may be viewed; for a sparse R (a SparseBlockLinearSystem) only stored blocks (the lower triangle, i >= j), else ArgumentError. rows and cols may be Int, StaticInt or Val and must equal the block's size (DimensionMismatch otherwise); static sizes give a SizedMatrix, as for block.

BlockLinearSystems.build_schur_pattern — Function
build_schur_pattern(structure::SchurStructure, [T=Float64]; extra_blocks=()) -> NamedTuple

Compute block-level and scalar-level sparsity patterns of the reduced system S, where two retained blocks are linked if they are coupled to a common eliminated block. Returns (block_pattern, block_colptr, block_rowval, block_row_offsets, col_heights, S_sparse, diag_inds); S_sparse is a zero-valued SparseMatrixCSC{T}.

QR Elimination (Jacobian Path)

The Jacobian-path counterpart of the Schur reduction: elimination of the same blocks from a tall least-squares problem min ‖J x - r‖² by QR. See the QR elimination tutorial.

BlockLinearSystems.SchurJacobianStructure — Type
SchurJacobianStructure(structure::SchurStructure, e_rows; free_rows=Int[], free_retained=Vector{Int}[], nchunks)
SchurJacobianStructure(r_dims, e_dims, couplings, e_rows; free_rows=Int[], free_retained=Vector{Int}[], nchunks=1)

Layout of a tall linear least-squares problem min ‖J x - r‖², x = [x_r; x_e] (retained variables first), partitioned like structure (same retained and eliminated blocks, same couplings, same block order). It is the Jacobian-path counterpart of a SchurStructure, and holds one, unchanged, in its schur field.

Every row of J involves at most one eliminated block (the Schur condition). The rows that involve eliminated block e form its table, e_rows[e] rows by the columns of every retained block coupled to e, then e's own columns, then the residual:

T_e = [ J_r | J_e | r ]        (e_rows[e] + d_e) × (c_e + d_e + 1)

where c_e is the sum of the coupled retained dimensions (at most structure.max_coupled_dim). The last d_e rows are damping rows, zero in the raw storage and written by reduce_qr!. Rows that involve no eliminated block are given as free groups: group g has free_rows[g] rows and the retained blocks free_retained[g], and its table is [ J_r | r ].

Tables are numbered t = 1:ntables: table e (e <= structure.neblocks) belongs to eliminated block e, table structure.neblocks + g to free group g. A table's retained blocks are its entries, numbered globally: entries 1:length(structure.entry_retained) are the coupling entries of structure (same index c, same order, sorted by retained block within each eliminated block), followed by the entries of the free groups (retained blocks sorted within each group). coupling_entry finds an entry from its table and retained block.

nchunks sets how many disjoint ranges of retained blocks (col_chunks) the column-ownership kernels are threaded over; it defaults to the number of chunks of structure.

Throws DimensionMismatch if e_rows (or free_retained) has the wrong length, and ArgumentError for a table with no rows, or a free group that references a retained block that does not exist or lists one twice.

Example

using BlockLinearSystems
# Two retained blocks (6 and 3), two eliminated blocks (3 and 3); 4 and 6 rows each; one free group of 2 rows
jst = SchurJacobianStructure([6, 3], [3, 3], [[1, 2], [2]], [4, 6]; free_rows=[2], free_retained=[[1]])
jst.ntables          # 3
reduced_nrows(jst)   # 4 + 6 + 2
BlockLinearSystems.SchurBlockJacobian — Type
SchurBlockJacobian{T}(structure::SchurJacobianStructure)
SchurBlockJacobian(data::Vector{T}, structure::SchurJacobianStructure)

Raw storage of a tall least-squares problem: the tables of structure (see SchurJacobianStructure), each column-major, in one flat vector data at structure.table_offsets. It is the Jacobian prototype a caller fills, the analogue of SchurBlockMatrix on the Hessian path. T may be any floating-point type; Float64 and Float32 are tested.

Fill it through coupling_block, eliminated_block and residual_block. The rows of a table belong to one eliminated block (or one free group), so threads that fill different tables never write the same memory and need no per-thread copies. The damping rows are not reachable through the views and stay zero. reduce_qr! reads these tables and never modifies them, so a change of the damping re-factors from them.

zero! zeroes every table; copy_structure returns a new, zeroed SchurBlockJacobian sharing only the (immutable) structure. schur_jacobian_bytes gives the memory needed before anything is allocated.

BlockLinearSystems.schur_jacobian_bytes — Function
schur_jacobian_bytes(structure::SchurJacobianStructure, T=Float64; workspace=true) -> Int

Bytes of element data a SchurBlockJacobian{T} for structure allocates and, with workspace=true, its QRReductionWorkspace{T} too (a factored copy of every table, plus scratch for eliminated blocks above BlockLinearSystems.D_STATIC dimensions). Computed from the structure alone, so a caller can refuse, or choose the Schur route, before allocating anything.

Each table is dense in every retained block coupled to its eliminated block, so its size is (m_e + d_e) × (c_e + d_e + 1): the memory grows with the number of rows times the coupled retained dimension, which for an eliminated block seen by many residuals is far more than the Schur route's d_e × c_e coupling blocks. The index arrays of the structure itself are not counted.

BlockLinearSystems.coupling_block — Function
coupling_block(J::SchurBlockJacobian, u)
coupling_block(J::SchurBlockJacobian, u, row, nrows[, ncols])

Mutable view of entry u's retained block in its table (u indexes entries as described in SchurJacobianStructure; use coupling_entry to find it): all of the table's rows, or rows row:row+nrows-1 (counted from 1 within the table). The view has nrows × d_r entries; ncols, if given, must equal d_r.

nrows and ncols may be Int, StaticInt or Val. With both static the view is a SizedMatrix, with one static a HybridArray, as for block; all forms are type stable and allocation free. Throws BoundsError for an unknown entry or rows outside the table's data rows (the damping rows are never reachable), and DimensionMismatch for a wrong ncols.

Example

using BlockLinearSystems, Static, StaticArrays
J = SchurBlockJacobian{Float64}(SchurJacobianStructure([6, 3], [3, 3], [[1, 2], [2]], [4, 6]))
u = coupling_entry(J.structure, 1, 2)                 # retained block 2 in eliminated block 1's table
coupling_block(J, u, 3, static(2), static(3)) .= @SMatrix rand(2, 3)   # rows 3:4 of that residual

eliminated_block(J::SchurBlockJacobian, e)
eliminated_block(J::SchurBlockJacobian, e, row, nrows[, ncols])

Mutable view of the eliminated columns J_e of table e (an eliminated block, so e <= J.structure.schur.neblocks): all of its data rows, or rows row:row+nrows-1. Sizes and errors as for coupling_block, with ncols == d_e.

BlockLinearSystems.residual_block — Function
residual_block(J::SchurBlockJacobian, t)
residual_block(J::SchurBlockJacobian, t, row, nrows)

Mutable view of the residual column of table t (an eliminated block's table or a free group's): all of its data rows, or rows row:row+nrows-1. A SizedVector for a static nrows, otherwise a plain view. The residual is r of min ‖J x - r‖²: callers that hold f(x) ≈ f(x0) + J dx store r = -f(x0), or store f(x0) and negate the step, as with the Schur systems.

coupling_entry(structure::SchurJacobianStructure, t, r) -> Int

Index of the entry of retained block r in table t (binary search). Throws ArgumentError if r is not coupled to table t, BoundsError for an unknown table.

BlockLinearSystems.QRReductionWorkspace — Type
QRReductionWorkspace{T}(structure::SchurJacobianStructure)
QRReductionWorkspace(J::SchurBlockJacobian)

Storage for QR elimination, the analogue of SchurReductionWorkspace: factored, a factored copy of every table in the layout of the raw storage (free tables are copied unchanged), per-chunk scratch for back-substitution of eliminated blocks above BlockLinearSystems.D_STATIC dimensions, and the failure flag failed_block (an Atomic{Int}: 0, or the lowest failing eliminated block).

After reduce_qr!, the top d_e rows of table e hold [B | U | q] with U upper triangular, and the rows below hold [J̃_e | 0 | r̃_e]. The Householder reflectors are not kept (nothing needs Q afterwards), so the eliminated columns hold exactly [U; 0] and each factored table equals Qᵀ times the damped raw table. All the kernels of the reduced problem read these tables.

trial_workspace gives a second workspace for a trial system with the same structure.

BlockLinearSystems.reduce_qr! — Function
reduce_qr!(ws::QRReductionWorkspace{T}, J::SchurBlockJacobian{T}, scaling_e, lambda) -> Bool

Eliminate every eliminated block of J by QR, into ws. For each eliminated block e:

  1. copy its raw table to ws.factored;
  2. write the damping rows [0 | √(lambda * scaling_e[e]) | 0] (a diagonal d_e × d_e block), so that the factored table represents [J; √λ·D] with D = Diagonal(√scaling_e);
  3. Householder-factor the eliminated columns, applying Qᵀ to the whole table in place.

This solves the eliminated part of (JᵀJ + λ·Diagonal(s)) x = Jᵀr; scaling_e (length sum(e_dims)) is the eliminated part of s, in the units of diag(JᵀJ) (for Marquardt scaling, jtj_diag!). The retained part of the damping is the caller's business: append rows to J̃, or add λ·s_r to the diagonal of J̃ᵀJ̃. lambda = 0 is undamped.

Returns false if an eliminated block is numerically singular — |U_kk| ≤ M·eps(T)·‖column k‖, with M the table's row count (the rounding left on an exactly dependent column grows with the number of rows), which catches under-determined (e_rows[e] < d_e), rank-deficient and zero blocks without damping — or its table contains a non-finite value; ws.failed_block[] then holds the lowest failing block, as for the Schur reduction. Free tables are copied, not checked.

Statically sized in the eliminated dimension (unrolled over the columns) up to BlockLinearSystems.D_STATIC, dynamic above, through the e_groups and chunks of the structure. Threaded over the chunks of eliminated blocks when there is enough work (BlockLinearSystems.SCHUR_THREAD_MIN_WORK); tables are independent, so there is no merge step. The raw tables are untouched, so calling it again with another lambda re-factors from them; it allocates nothing on the serial path (a threaded launch costs Polyester a small constant allocation).

BlockLinearSystems.reduced_nrows — Function
reduced_nrows(structure::SchurJacobianStructure) -> Int

Number of rows of the reduced Jacobian J̃: e_rows[e] rows per eliminated block, then the free rows. Fixed by the structure, whatever λ is: each table has e_rows[e] + d_e rows, of which d_e become U. When λ = 0 the damping rows are zero and remain so, so d_e of each block's reduced rows are zero (and contribute nothing).

BlockLinearSystems.free_block_pairs — Function
free_block_pairs(structure::SchurJacobianStructure) -> Vector{Tuple{Int, Int}}

The pairs (r1, r2), r1 < r2, of retained blocks coupled through a free group. Pass them as extra_blocks to build_schur_pattern, so that the sparse reduced system has a slot for them: build_schur_pattern(structure.schur; extra_blocks=free_block_pairs(structure)).

BlockLinearSystems.reduced_mul! — Function
reduced_mul!(y, ws::QRReductionWorkspace, v) -> y

y = J̃ v, with v over the retained variables (length nr) and y over the reduced rows (length reduced_nrows), in the documented order: the bottom rows of eliminated block 1's table, block 2's, …, then each free group's rows. Threaded over tables, allocation free on the serial path.

BlockLinearSystems.reduced_tmul! — Function
reduced_tmul!(g, ws::QRReductionWorkspace, w) -> g

g = J̃ᵀ w, with w over the reduced rows (in the order of reduced_mul!). Threaded by retained column ownership (structure.col_chunks), so no two threads write the same entry.

BlockLinearSystems.reduced_residual! — Function
reduced_residual!(rt, ws::QRReductionWorkspace) -> rt

r̃, the right-hand side of the reduced problem min ‖J̃ x_r - r̃‖², in the row order of reduced_mul!.

BlockLinearSystems.reduced_jacobian! — Function
reduced_jacobian!(Jt::AbstractMatrix, rt::AbstractVector, ws::QRReductionWorkspace) -> Jt

Write the reduced problem densely: Jt = J̃ (size (reduced_nrows(structure), nr), overwritten) and rt = r̃, for a dense QR of the reduced problem. Solving that by QR, then backsubstitute!, keeps the whole solve at the condition number of J; forming J̃ᵀJ̃ squares it.

BlockLinearSystems.reduced_normal_dense! — Function
reduced_normal_dense!(S::Matrix, g_S, ws::QRReductionWorkspace) -> true

Overwrite S with the upper triangle of J̃ᵀJ̃ (the strict lower triangle is zeroed) and g_S with J̃ᵀr̃. These equal the Schur complement S and right-hand side g_S that reduce_schur_dense! produces from H = JᵀJ and b = Jᵀr, apart from the retained damping, which the Schur route adds and this one leaves to the caller (S[i, i] += λ * s_r[i]). Threaded by retained column ownership, as accumulate_dense_columns! is.

BlockLinearSystems.reduced_normal_sparse! — Function
reduced_normal_sparse!(S::SparseMatrixCSC, g_S, ws::QRReductionWorkspace, pattern) -> true

Sparse counterpart of reduced_normal_dense!: overwrite S.nzval (upper triangle) and g_S. pattern and S come from build_schur_pattern(structure.schur, T; extra_blocks=free_block_pairs(structure)) (copy pattern.S_sparse for S); add the retained damping at pattern.diag_inds. Throws an AssertionError if the pattern lacks a needed block.

BlockLinearSystems.reduced_diagonal_blocks! — Function
reduced_diagonal_blocks!(D::AbstractVector, ws::QRReductionWorkspace) -> D

The diagonal blocks of J̃ᵀJ̃, one full (both triangles) column-major d_r × d_r block per retained block, block r at D[structure.doffsets[r]:structure.doffsets[r+1]-1]; for block-Jacobi preconditioning of an iterative solve on J̃.

BlockLinearSystems.jtr! — Function
jtr!(g, src::Union{SchurBlockJacobian, QRReductionWorkspace}) -> g

The gradient g = Jᵀr of the full problem, [g_r; g_e] (length nr + sum(e_dims)), from the raw tables or the factored ones: Q is orthogonal and the damping rows have zero residual, so both give the same result (to rounding), for any λ.

BlockLinearSystems.jtj_diag! — Function
jtj_diag!(d, src::Union{SchurBlockJacobian, QRReductionWorkspace}) -> d

The squared column norms of J, i.e. diag(JᵀJ), [d_r; d_e], for Marquardt scaling and for the largest diagonal entry. From the raw tables this is diag(JᵀJ); from the factored tables it is that of the damped Jacobian [J; √(λ s_e)], so the eliminated entries include λ * s_e (equal at λ = 0).

BlockLinearSystems.factor_eliminated! — Function
factor_eliminated!(E_inv_data, z_data, W_data, scratch, structure, E_data, C_data, b_e, scaling_e, lambda, e, s_de)

Phase 1 for eliminated block e: invert E_e + lambda * diag(scaling), cache E_inv and z_e = E_inv * b_e, and store W_er = E_inv * C_er for every coupled retained block in W_data. Returns false if the damped block is numerically singular or not positive definite.

s_de is a StaticInt for blocks of up to D_STATIC dimensions (register arithmetic), otherwise the Int dimension, which uses a LAPACK Cholesky on the scratch matrix (O(d^3) per eliminated block plus O(d^2) per coupling row; no allocation).
