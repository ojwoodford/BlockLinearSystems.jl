API Reference

Linear System Types

BlockLinearSystems.SparseBlockLinearSystem — Type
SparseBlockLinearSystem{T}(sparsitytransposed::SparseMatrixCSC{Bool, Int}, rowblocksizes, colblocksizes=rowblocksizes)
SparseBlockLinearSystem{T}(nnzvals, indicestransposed, rowblocksizes, colblocksizes=rowblocksizes)

Cache-friendly block-sparse matrix storing each non-zero block contiguously in column-major order within a flat data::Vector{T} buffer.

The block sparsity pattern is provided transposed (sparsitytransposed has size (length(colblocksizes), length(rowblocksizes))) so that blocks along a block-row are contiguous in the CSC structure of indicestransposed.

Fields

  • data::Vector{T}: Contiguous storage for all non-zero block entries.
  • indices::SparseMatrixCSC{Int, Int}: Cached start indices in data for each block (row, col).
  • indicestransposed::SparseMatrixCSC{Int, Int}: Transposed start indices in data (indicestransposed[col, row]).
  • rowblocksizes::Vector{UInt8}: Row dimensions of each block row.
  • columnblocksizes::Vector{UInt8}: Column dimensions of each block column.
  • m::Int: Total number of scalar rows.
  • n::Int: Total number of scalar columns.

Example

using BlockLinearSystems, SparseArrays

sparsity_t = sparse([true false; true true])
bsm = SparseBlockLinearSystem{Float64}(sparsity_t, [2, 3], [2, 3])
block(bsm, 1, 1) .= [1.0 2.0; 2.0 4.0]
BlockLinearSystems.DenseBlockLinearSystem — Type
DenseBlockLinearSystem{T}(rowblockoffsets, columnblockoffsets=rowblockoffsets)
DenseBlockLinearSystem{T}(data::AbstractMatrix{T}, rowblockoffsets, columnblockoffsets=rowblockoffsets)
DenseBlockLinearSystem(data::AbstractMatrix{T}, rowblockoffsets, columnblockoffsets=rowblockoffsets)

Block-partitioned dense matrix backed by a matrix buffer data (such as Matrix{T}, SubArray, or FixedSizeMatrix{T}) alongside 1-based sentinel-terminated block offset vectors rowblockoffsets and columnblockoffsets.

Fields

  • data::AbstractMatrix{T}: Underlying matrix buffer of size (rowblockoffsets[end]-1, columnblockoffsets[end]-1).
  • rowblockoffsets::Vector{Int}: 1-based start row of each block row, terminated by m + 1.
  • columnblockoffsets::Vector{Int}: 1-based start column of each block column, terminated by n + 1.

Example

using BlockLinearSystems

bdm = DenseBlockLinearSystem{Float64}([1, 3, 6]) # Two blocks of sizes 2 and 3
block(bdm, 2, 1) .= reshape(1.0:6.0, 3, 2)

Block Indexing & Accessors

BlockLinearSystems.block — Function
block(M, i, j)
block(M, i, j, rows, cols)

Returns a mutable view into block (i, j) of M (SparseBlockLinearSystem or DenseBlockLinearSystem). When rows and/or cols are passed as StaticInt, returns a stack-wrapped SizedMatrix or HybridArray view for SIMD-accelerated block operations.

Example

using BlockLinearSystems, Static

bdm = DenseBlockLinearSystem{Float64}([1, 3, 5])
B = block(bdm, 1, 1, static(2), static(2))
B .= 1.0
BlockLinearSystems.blockrange — Function
blockrange(first, len) -> AbstractUnitRange

Index range of a block of len entries starting at index first. A StaticInt len gives a statically sized range; any other integer len gives a plain UnitRange{Int}, so views built with it are type stable and allocation free even when the size is only known at run time. Integer sizes of any type (including the UInt8 sizes stored by BlockRLE) are widened to Int before use.

BlockLinearSystems.validblock — Function
validblock(M, i, j) -> Bool

Returns true if block (i, j) is structurally present in M (always true for DenseBlockLinearSystem, and M.indicestransposed[j, i] != 0 for SparseBlockLinearSystem).

Example

using BlockLinearSystems, SparseArrays

validblock(bsm, 2, 1) # false

Conversion & Symmetrification

BlockLinearSystems.symmetrifyfull — Function
symmetrifyfull(M) -> Matrix{T}

Constructs a full symmetric Matrix{T} from a lower-triangular block matrix M (SparseBlockLinearSystem or DenseBlockLinearSystem). Allocates and returns a new symmetric Matrix{T}. See symmetrifyfull! for the in-place version.

Example

using BlockLinearSystems

bdm = DenseBlockLinearSystem{Float64}([1, 3, 5])
bdm[3, 1] = 4.0
mat = symmetrifyfull(bdm) # mat[1, 3] == 4.0, mat !== bdm.data
BlockLinearSystems.symmetrifyfull! — Function
symmetrifyfull!(bdm::DenseBlockLinearSystem) -> AbstractMatrix{T}
symmetrifyfull!(mat::AbstractMatrix{T}, bsm::SparseBlockLinearSystem{T}, blocks=nothing)

Symmetrifies a lower-triangular block matrix in-place:

  • For DenseBlockLinearSystem: mirrors the lower triangle to the upper triangle of bdm.data in-place and returns bdm.data.
  • For SparseBlockLinearSystem: populates preallocated dense matrix mat in-place. If blocks is a vector of block indices, extracts and symmetrifies only the principal submatrix corresponding to blocks.

Example

using BlockLinearSystems, SparseArrays

bsm = SparseBlockLinearSystem{Float64}(sparse([true true; false true]), [2, 2], [2, 2])
block(bsm, 2, 1) .= 3.0
mat = zeros(4, 4)
symmetrifyfull!(mat, bsm)
BlockLinearSystems.symmetrifysparse — Function
symmetrifysparse(bsm::SparseBlockLinearSystem{T}) -> SparseMatrixCSC{T, Int}

Converts a block-lower-triangular SparseBlockLinearSystem into a full symmetric SparseMatrixCSC{T, Int} by mirroring off-diagonal blocks to the upper triangle.

Example

using BlockLinearSystems, SparseArrays

bsm = SparseBlockLinearSystem{Float64}(sparse([true true; false true]), [2, 2], [2, 2])
block(bsm, 2, 1) .= 5.0
S = symmetrifysparse(bsm)
BlockLinearSystems.makesparseindices — Function
makesparseindices(bsm::SparseBlockLinearSystem, symmetrify::Bool=false) -> SparseMatrixCSC{Int, Int}

Precomputes a SparseMatrixCSC{Int, Int} whose nzval holds the 1-based indices into bsm.data for every scalar non-zero entry of sparse(bsm) (or symmetrifysparse(bsm) when symmetrify=true).

This enables zero-allocation copying from bsm.data into an existing SparseMatrixCSC via H.nzval[i] = bsm.data[sparseindices.nzval[i]].

Example

using BlockLinearSystems, SparseArrays

bsm = SparseBlockLinearSystem{Float64}(sparse([true true; false true]), [2, 2], [2, 2])
idx_csc = makesparseindices(bsm, true)
S = sparse(bsm, idx_csc)
BlockLinearSystems.sparse_with_map — Function
sparse_with_map(sparse_sys::SparseBlockLinearSystem{T}; symmetric::Bool=false) -> (SparseMatrixCSC{T, Int}, Vector{Int})
sparse_with_map(sparse_sys::SparseBlockLinearSystem{T}, sparse_idx::SparseMatrixCSC{Int, Int}) -> (SparseMatrixCSC{T, Int}, Vector{Int})

Precomputes a standard SparseMatrixCSC{T, Int} alongside a scatter_map::Vector{Int}. The scatter_map maps entries from sparse_sys.data to the CSC nonzeros vector.

Subsequent updates can be performed in-place with zero allocations via:

copyto!(csc_mat, sparse_sys, scatter_map)

Example

using BlockLinearSystems, SparseArrays

sys = SparseBlockLinearSystem{Float64}(sparse([true true; true true]), [2, 2])
block(sys, 1, 1) .= 1.0
csc_mat, scatter_map = sparse_with_map(sys; symmetric=false)

# In-place update in solver loop (0 allocations):
block(sys, 1, 1) .= 2.0
copyto!(csc_mat, sys, scatter_map)

Run-Length Encoded Block Arrangements

BlockLinearSystems.BlockRLE — Type
BlockRLE(runlengths, blocksizes)
BlockRLE(runs::Vector{Pair})
BlockRLE(vec::AbstractVector{<:Integer})

Run-Length Encoded (RLE) block layout metadata capturing contiguous runs of uniform block sizes. Subtypes AbstractVector{Int} (storing the sizes compactly, normally as UInt8, but always returning Int) for transparent interop with all linear systems while providing $O(1)$ matrix dimension lookup, $O(1)$ run indexing, and $O(\log R)$ block-to-coordinate mapping.

Fields

  • runlengths::Vector{Int}: Number of blocks in each run.
  • blocksizes::Vector{UInt8}: Block dimension in each run.
  • cumblocks::Vector{Int}: 1-based start block index for each run, terminated by total_blocks + 1.
  • cummatrixdims::Vector{Int}: 1-based start scalar matrix coordinate for each run, terminated by total_dimension + 1.

Example

# 100 blocks of dimension 6 followed by 50,000 blocks of dimension 3:
rle = BlockRLE([100, 50_000], [6, 3])
length(rle)            # 50100
matrixdimension(rle)   # 150600
nruns(rle)             # 2

Schur Complement Reduction

Data structures and kernels for bipartite problems, where a few retained variable blocks are coupled to many small eliminated variable blocks. See the Schur reduction tutorial.

BlockLinearSystems.SchurStructure — Type
SchurStructure

Metadata describing bipartite variable partitioning, block offsets, and coupling sparsity.

BlockLinearSystems.SchurBlockMatrix — Type
SchurBlockMatrix{T, BType}

Block Hessian structure partitioned into retained block B, eliminable blocks C_data, coupling blocks E_data, and bipartite indexing structure::SchurStructure.

BlockLinearSystems.SchurReductionWorkspace — Type
SchurReductionWorkspace{T}

Pre-allocated scratch memory and caches for parallel Schur reduction and back-substitution.

The reduction runs in two phases. Phase 1 (parallel over chunks of eliminated blocks) factors every C_l, caching C_inv, z_l and W_cl = C_inv * E_cl' (W_data, laid out like E_data). Phase 2 (parallel over col_chunks, disjoint ranges of retained blocks) has each chunk write straight into the columns of S (and entries of g_S) that it owns, so no per-chunk copies of S are needed and nothing has to be merged afterwards.

BlockLinearSystems.backsubstitute! — Function
backsubstitute!(x_p, x_c, structure, E_data, C_inv_data, z_data)

Recover step Delta xp for all eliminable blocks independently using cached Cinv and z: x_p,l = z_l - C_inv,l * (sum_c E_cl' x_c,c). The coupling sum is accumulated first and C_inv is applied once per eliminable block.

BlockLinearSystems.fast_bAb — Function
fast_bAb(H::SchurBlockMatrix, dx::AbstractVector) -> Real

Compute quadratic form dx' * H * dx in O(N) operations without materializing the full Hessian. dx may have any element type; the result has the promoted type.

The retained part (B) is walked block by block. The eliminated part (C and the couplings E) is where nearly all the work is, and is processed per group of eliminated blocks of uniform dimension with that dimension known statically (3.4x faster than per-block run-time sizes on a bundle-adjustment-like benchmark with 200 retained and 20000 eliminated blocks). Specialising the retained part by run of retained block sizes was measured too: it saved nothing measurable (that part takes ~0.01 ms) and cost 0.2-2 s of extra compilation, so it is not done.

Reduced-System Sparsity

BlockLinearSystems.build_schur_pattern — Function
build_schur_pattern(structure::SchurStructure, [T=Float64]; extra_blocks=()) -> NamedTuple

Compute block-level and scalar-level sparsity patterns of the reduced system S, where two retained blocks are linked if they are coupled to a common eliminated block. Returns (block_pattern, block_colptr, block_rowval, block_row_offsets, col_heights, S_sparse, diag_inds); S_sparse is a zero-valued SparseMatrixCSC{T}.

The pattern contains every pair of retained blocks that share an eliminated block, plus the diagonal. Retained-retained couplings that do not go through an eliminated block (direct couplings between retained blocks that share no eliminated block) have no such slot, so list them in extra_blocks, an iterable of (i, j) retained block index pairs (in either order; i == j is allowed and ignored). Use retained_block_pairs to obtain them from the block pattern of B.

BlockLinearSystems.retained_block_pairs — Function
retained_block_pairs(B::SparseBlockLinearSystem) -> Vector{Tuple{Int, Int}}

Off-diagonal stored blocks of B as (row_block, col_block) pairs. Pass them as extra_blocks to build_schur_pattern so the reduced system has a slot for every coupling in B.

sort_schur_blocks(is_eliminable::AbstractVector{Bool}, block_sizes::AbstractVector{<:Integer}, couplings::AbstractVector{<:AbstractVector{<:Integer}}) -> Vector{Int}

Two-pass variable ordering:

  • Pass 1: Retained variables (role 0) ordered by dimension descending; eliminable variables (role 1) grouped by dimension descending.

Schur Reduction Kernels

BlockLinearSystems.factor_eliminated! — Function
factor_eliminated!(C_inv_data, z_data, W_data, scratch, structure, C_data, E_data, b_p, scaling_p, lambda, l, s_dp)

Phase 1 for eliminated block l: invert C_l + lambda * diag(scaling), cache C_inv and z_l = C_inv * g_p,l, and store W_cl = C_inv * E_cl' for every coupled retained block in W_data. Returns false if the damped block is numerically singular or not positive definite.

s_dp is a StaticInt for blocks of up to D_STATIC dimensions (register arithmetic), otherwise the Int dimension, which uses a LAPACK Cholesky on the scratch matrix (O(d^3) per eliminated block plus O(d^2) per coupling row; no allocation).
