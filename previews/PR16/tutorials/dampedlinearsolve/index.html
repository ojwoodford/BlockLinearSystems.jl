Solving with DampedLinearSolve.jl

DampedLinearSolve.jl defines the linear-system contract a second-order optimizer uses: build a system from a prototype, fill it, damp it, solve it, and query it (see its documentation, "The linear-system contract"). Loading it with this package activates the extension DampedLinearSolveExt, which implements that contract for this package's eliminated systems, so that any optimizer written against the contract (SecondOrderOptimization.jl, for one) runs on them unchanged.

Which system a prototype builds

PrototypeSystemlinsolver for the reduced system
SchurBlockHessian with a dense Rdense Schur complement:auto, :cholesky (Cholesky, falling back to Bunch–Kaufman), :ldl (Bunch–Kaufman)
SchurBlockHessian with a SparseBlockLinearSystem Rsparse Schur complement:auto, :cholesky (CHOLMOD, falling back to LDLᵀ), :ldl (LDLᵀ)
SchurBlockJacobian{Float64, Matrix{Float64}}QR elimination, dense reduced system:auto, :qr (QR of the reduced Jacobian); :cholesky, :ldl (its normal equations); :lsmr (with Krylov.jl)
SchurBlockJacobian{Float64, SparseMatrixCSC{Float64, Int}}QR elimination, sparse reduced system:auto, :qr (SPQR of the reduced Jacobian); :cholesky, :ldl (its normal equations); :lsmr (with Krylov.jl)

makelinearsystem(H, linsolver) builds the Schur systems and maketallsystem(J, n, linsolver) the QR-eliminated ones; checkhessian, checkjacobian and check_jacobian_linsolver validate a prototype first, and structurekey identifies its structure for a cache.

How a solve goes

Each solve applies the recorded damping λ·Diagonal(s) during the reduction (to R and to each eliminated block, so that the eliminated blocks are inverted damped), reduces to the retained variables, solves the reduced system, and back-substitutes for the eliminated ones. The reduced system is itself a DampedLinearSolve system wherever a standard one holds it exactly:

  • a dense reduced matrix S, or dense reduced normal equations, is an undamped dense system;
  • the dense reduced least-squares problem [J̃; √(λ s_r)] x_r ≈ [r̃; 0] is an undamped dense tall system, so its single Householder QR is of the whole augmented matrix;
  • the sparse reduced Jacobian is a sparse tall system, damped by λ s_r, solved by SPQR with its symbolic analysis done once;
  • LSMR on the reduced Jacobian (with Krylov.jl loaded) is a matrix-free reduced system of the extension DampedLinearSolveKrylovExt: J̃ is applied through the factored tables and never formed.

A sparse reduced matrix S (the sparse Schur system, and the sparse reduced normal equations) is solved by the extension itself, with a persistent CHOLMOD copy and LDLFactorizations' upper-triangle LDLᵀ: the reduction writes one triangle of S, and a DampedLinearSolve sparse system stores the full symmetric matrix.

An example

using BlockLinearSystems, DampedLinearSolve

H = SchurBlockHessian(structure, zeros(nr, nr), zeros(sum(abs2, e_dims)), zeros(clen))   # dense R
ls = makelinearsystem(H, :auto)
# fill getA(ls) (the SchurBlockHessian: R, E and C blocks) and getb(ls), then
dampen!(ls, 1e-3)
solve!(ls, :auto)        # Success; getx(ls) holds [x_r; x_e]

Conformance

Every one of these systems passes DampedLinearSolve's check_linear_system in this package's test suite, for each solver it accepts; the extension provides the conformance hooks (conformance_matrix, conformance_fill!, conformance_fillb!, conformance_traits) for a SchurBlockHessian and the tables of a SchurBlockJacobian.
